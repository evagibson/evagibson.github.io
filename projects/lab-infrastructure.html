My home lab: eight VMs behind a pfSense firewall

I planned, built and documented my own lab in VirtualBox: a pfSense router and firewall, three VLANs, and Linux, Windows and Docker servers, each set up for its role.

Role it supports
Cloud / Infrastructure Engineer, Sysadmin, DevOps
Setting
Home lab
Tools
VirtualBox, pfSense, VLANs, DHCP, Ubuntu, Debian, Kali, Windows Server 2022, Windows 10, Docker, Portainer

The problem

I wanted my own lab to practise on: user machines, servers, a firewall between them, and an isolated zone for attack testing. A single computer can't give you that, so I built the whole environment from virtual machines and wrote down every step so I could rebuild it, or hand it to someone else.

What I built

Eight virtual machines in VirtualBox on one host, connected through a pfSense router and firewall that splits the network into three VLANs. Each machine has a clear role.

How I did it

  1. Installed pfSense as the router and firewall

    I built the pfSense VM first, because every other machine depends on it for addresses and internet access. It has two virtual network adapters: one on VirtualBox's NAT network as the WAN, and one on an internal network as the LAN. I booted the installer and accepted the defaults.

  2. Configured the interfaces

    From the pfSense console, I assigned the WAN and LAN interfaces and set the LAN address. Then I finished the setup wizard in the web interface: hostname, DNS servers, time zone, and a new admin password in place of the default.

  3. Added Kali as the first client

    I installed Kali Linux next and used its browser to reach the pfSense web interface and finish the network configuration.

  4. Split the network into three VLANs

    In Interfaces → Assignments → VLANs, I created VLAN tags 10, 20 and 30 on the LAN adapter, assigned each as its own interface, and gave each a gateway and a DHCP range. This is the same subnetting and routing work as planning subnets in a cloud VPC.

    VLANPurposeGatewayDHCP range
    10Users10.10.10.1/2410.10.10.100–200
    20Servers10.10.20.1/2410.10.20.100–200
    30Attack lab10.10.30.1/2410.10.30.5–50

  5. Set baseline firewall rules on every VLAN

    New pfSense interfaces block all traffic, so I added the rules each zone needs in Firewall → Rules. To keep them consistent, I built them on VLAN 10 first, copied each rule, and pasted it into VLAN 20 and VLAN 30, changing the source. Each change was saved and applied before I moved on. The full rule set is in Project 04.

  6. Built the Ubuntu Docker host

    On an Ubuntu Server VM in VLAN 20, I removed any old container packages and installed Docker Engine from Docker's official repository, which gets updates faster than Ubuntu's own package.

    Ubuntu, Docker host
    for pkg in docker.io docker-doc docker-compose docker-compose-v2 podman-docker containerd runc; do sudo apt-get remove $pkg; done

# Add Docker's official GPG key and repository
sudo apt-get update
sudo apt-get install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update

sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker run hello-world
sudo docker ps

  7. Added Portainer to manage containers

    I ran Portainer as a container with a persistent volume, so its settings survive restarts, and set it to restart automatically.

    Ubuntu, Docker host
    sudo docker volume create portainer_data
sudo docker run -d -p 8000:8000 -p 9443:9443 --name portainer --restart=always \
  -v /var/run/docker.sock:/var/run/docker.sock -v portainer_data:/data \
  portainer/portainer-ce:latest
sudo docker ps

    At https://<docker-host-ip>:9443 I created the admin account, went to Home, and connected to the local Docker environment. Portainer locks its first-run page after a few minutes for safety, and sudo docker restart portainer reopens it.

  8. Built the Metasploitable 2 target

    Metasploitable 2 comes as a ready-made virtual disk. I created a VM around it on VLAN 30 at 10.10.30.8 and signed in with its default msfadmin account. Keeping it on its own VLAN means it can't reach anything that matters.

  9. Installed Windows Server 2022 and Windows 10

    I installed Windows Server 2022 and Windows 10 on VLAN 10 to give the lab a Windows server and a Windows desktop. The server restarts itself once installation finishes.

  10. Built the Splunk server with a desktop

    For the SIEM server, I started from Ubuntu and added a desktop environment so I could use Splunk's web interface directly on the machine.

    Ubuntu, SIEM server
    sudo apt install tasksel
sudo tasksel install ubuntu-desktop
sudo reboot

    Installing and configuring Splunk itself is covered in Project 04.

  11. Added a Debian server

    Finally, I built a Debian VM in VLAN 20, so the lab has a second Linux distribution alongside Ubuntu.

  12. Tested that every machine could reach what it needs

    Last, I checked each VM got an address from the right VLAN and could reach its gateway and the internet. Then I checked that the zones were separated where they should be, for example that Metasploitable 2 couldn't reach VLAN 10.

    Any Linux VM
    ip -4 addr show          # address from the expected VLAN range
ping -c 3 10.10.20.1     # own gateway
ping -c 3 8.8.8.8        # internet through pfSense NAT

What I found

  • Building in dependency order paid off: router first, then network design, then rules, then servers. Each new VM came up with an address and internet access straight away.
  • Copying firewall rules between VLANs and then editing them was faster and less error-prone than writing each set from scratch.
  • Writing the build down as I went turned into this guide, which is the same habit infrastructure teams need for documenting processes and configurations.
If you seeCause and fix
A VM gets no IP addressIts VirtualBox adapter isn't attached to the lab's internal network, or DHCP isn't enabled on that VLAN's interface.
VMs get addresses but no internetThe VLAN's firewall rules don't allow outbound traffic yet, or pfSense's WAN adapter isn't set to NAT in VirtualBox.
Portainer's setup page times outRun sudo docker restart portainer and finish setup within a few minutes.
